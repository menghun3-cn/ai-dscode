# DSCODE 需求文档

> 版本：v0.1 · 状态：基线需求，增量演进
> 配套：架构文档.md / 成功标准.md / todos-list.md

---

## 1. 背景与目标

开发者需要一个**对接 DeepSeek 优先、终端原生、开源可扩展**的 AI 编码助手（AI IDE CLI）。

市面上 Claude Code / Cursor / Codex / Grok / opencode / pi / Kiro 各有所长，但：
- 多以 Anthropic/OpenAI 为一等公民，DeepSeek 多为"能用但不优"。
- 中文场景、国内网络、私有化部署未被特别关照。
- 闭源者多，可二次开发受限。

**DSCODE 目标**：站在这些成熟产品的肩膀上，做一款 DeepSeek 一等公民、中文友好、开源、可扩展、headless 同等公民的 CLI。

### 1.1 目标用户

| 用户 | 场景 |
|------|------|
| 国内 DeepSeek 用户 | 日常用 DS 写代码，想要 Claude Code 体验但 DS 优先 |
| 私有化/可控成本团队 | 不走 SaaS，本地运行，团队可定 prompt/工具 |
| CI/headless 用户 | 在流水线里跑代码审查、自动修复、生成文档 |
| AI 工具开发者 | 想写自定义工具/命令接自己的业务 |
| 多模型尝鲜者 | 一个 CLI 切换 DeepSeek/OpenAI/Anthropic/本地 |

### 1.2 非目标（明确不做）

- ❌ GUI IDE 插件（rpc 模式为其留接口，但 v1 不做插件本身）
- ❌ Tab 补全专用本地模型
- ❌ 托管 SaaS 后端
- ❌ 训练自有模型
- ❌ IDE 强绑定

## 2. 用户故事

### US-1 首次使用
> 作为开发者，我在仓库目录运行 `dscode`，它引导我配置 DeepSeek key，然后我就能用自然语言驱动它读写文件、跑命令。

### US-2 单次任务（headless）
> 作为 CI 工程师，我在流水线执行 `dscode -p "审查本次 PR 的改动并指出风险" --mode json`，拿到结构化结果。

### US-3 多轮重构
> 作为后端开发者，我说"把 auth 模块从 callback 改成 async/await 并补测试"，dscode 自己读文件、改文件、跑测试、报错再改，直到测试通过。

### US-4 会话恢复
> 作为开发者，我昨天有个长会话在重构，今天 `dscode -c` 接着干，上下文不丢。

### US-5 分支探索
> 作为开发者，我对同一个问题想试两种方案，用 `/tree` 在历史节点分叉，比完留下更好的。

### US-6 切换模型
> 作为尝鲜者，复杂任务用 `deepseek-reasoner`，简单任务切 `deepseek-chat`，偶尔 `/model` 切到 GPT 比对效果。

### US-7 安全约束
> 作为团队负责人，我配置 `.dscode/permissions.json` 禁止写 `.env`、禁止 `rm -rf`，成员误操作也不会炸。

### US-8 自定义工具
> 作为平台开发者，我写个扩展注册 `deploy` 工具，让 dscode 改完代码自己调用我的发布脚本。

### US-9 中文体验
> 作为中文用户，我想要中文默认提示、中文错误信息、中文文档，模型输出也偏好中文。

### US-10 规格驱动
> 作为架构师，我用 Plan mode 先让它出方案不动手，我 review 后再让它落地。

## 3. 功能需求

### FR-1 启动与鉴权
- FR-1.1 `dscode` 无参启动进入交互模式。
- FR-1.2 首次启动无 DeepSeek key 时，引导输入并存 `~/.dscode/auth.json`（0600）。
- FR-1.3 支持环境变量 `DEEPSEEK_API_KEY`、`DSAPI_API_KEY`/`DSAPI_BASE_URL`（兼容用户既有环境）。
- FR-1.4 支持自定义网关/代理：`HTTP(S)_PROXY`、`baseUrl` 覆盖。
- FR-1.5 `--api-key` / `--provider` / `--model` 启动覆盖。

### FR-2 模式
- FR-2.1 **interactive**（默认）：TUI 交互，支持多行输入、`@` 文件引用、`!` 跑命令、粘贴图片。
- FR-2.2 **print**（`-p`）：一次性首尾，支持 stdin 管道，纯文本输出。
- FR-2.3 **json**（`--mode json`）：JSON event 流，CI 友好。
- FR-2.4 **rpc**（`--mode rpc`）：JSON-RPC over stdio，供 IDE 扩展宿主。

### FR-3 内置工具
- FR-3.1 `read`：读文件，offset/limit，图片作为附件回传模型。
- FR-3.2 `write`：创建/覆盖文件，自动建父目录。
- FR-3.3 `edit`：精确文本替换，单次多 disjoint edit，oldText 全文唯一匹配。
- FR-3.4 `bash`：执行 shell，超时/信号/cwd/truncation，输出回传模型。
- FR-3.5 `glob`：文件 glob 匹配。
- FR-3.6 `grep`：内容正则搜索（优先 ripgrep）。
- FR-3.7 `ls`：列目录。
- FR-3.8 `webfetch`：抓 URL（feed 模型理解外部内容）。
- FR-3.9 `task`：sub-agent，隔离上下文执行子任务。

### FR-4 Agent Loop
- FR-4.1 循环直到无 tool_call 或达上限（默认 50，可配）。
- FR-4.2 流式渲染模型输出。
- FR-4.3 并行执行同一 assistant message 的多个 tool_call（可配串行）。
- FR-4.4 自动重试（限流/网络错误，指数退避）。

### FR-5 Session
- FR-5.1 JSONL 树状存储于 `~/.dscode/sessions/<cwd-hash>/`。
- FR-5.2 自动保存，`dscode -c` 继续、`dscode -r` 浏览。
- FR-5.3 `/tree` 跳节点、`/fork` 新建分叉、`/clone` 复制当前分支。
- FR-5.4 `/name` 命名，便于检索。
- FR-5.5 `/export` 导出 HTML/mardown。

### FR-6 多 Provider / 模型切换
- FR-6.1 内置 DeepSeek 目录（`deepseek-chat`/`deepseek-reasoner`），随版本更新可拉远端目录缓存。
- FR-6.2 OpenAI、Anthropic、OpenRouter、本地 OpenAI 兼容（vLLM/Ollama/LM Studio）。
- FR-6.3 `/model` 交互切换、`--model` 启动指定、Ctrl+P 循环。
- FR-6.4 reasoning 模型（`deepseek-reasoner`）的 `reasoning_content` 解析与展示。
- FR-6.5 模型计费统计（input/output/cache token + 成本），`/cost` 查看。

### FR-7 上下文与配置
- FR-7.1 `DSCODE.md`（项目）+ `~/.dscode/DSCODE.md`（全局）注入 system prompt。
- FR-7.2 `.dscode/steering/*.md` steering 注入（借鉴 Kiro）。
- FR-7.3 `.dscode/settings.json`（项目）+ `~/.dscode/settings.json`（全局）。
- FR-7.4 `/reload` 热重载配置与扩展。
- FR-7.5 启动加载父目录链上的 `DSCODE.md`。

### FR-8 权限与审批
- FR-8.1 四级模式：`read-only` / `ask`（默认）/ `auto-edit` / `full-auto`。
- FR-8.2 `.dscode/permissions.json`：`allow`/`deny`/`ask` 规则（glob + 命令前缀）。
- FR-8.3 危险命令（`rm -rf`、`sudo`、`git push --force` 等）始终二次确认（除非 full-auto + allow）。
- FR-8.4 项目扩展需 `project_trust` 显式信任。

### FR-9 Plan 模式
- FR-9.1 `/plan` 进入只读规划，工具调用受限（不能 write/edit/bash 写操作）。
- FR-9.2 产出计划文档，用户 `/accept-plan` 后落地。

### FR-10 扩展系统
- FR-10.1 事件 hook（见架构文档事件清单）。
- FR-10.2 `registerTool` / `registerCommand` / `registerShortcut` / `registerFlag`。
- FR-10.3 `ctx.ui`：select/confirm/input/notify/custom TUI 组件。
- FR-10.4 扩展 TS 原生加载（jiti）。
- FR-10.5 全局（`~/.dscode/extensions/`）+ 项目（`.dscode/extensions/`，需信任）。

### FR-11 MCP（v0.6）
- FR-11.1 MCP client，接入第三方 MCP server。
- FR-11.2 MCP 工具/资源注入模型可用工具集。

### FR-12 Compaction
- FR-12.1 阈值（contextWindow 80%）自动摘要旧消息。
- FR-12.2 `/compact [指令]` 手动。
- FR-12.3 overflow 恢复（超长 abort → 压缩 → 重试）。
- FR-12.4 分支切换 branch summary。

### FR-13 中文与本地化
- FR-13.1 默认中文 system prompt 与错误信息。
- FR-13.2 中文文档（docs 全套中文）。
- FR-13.3 TUI 适配中文宽度（全角字符）。
- FR-13.4 输入法（IME）候选框定位支持。

### FR-14 分发
- FR-14.1 `npm i -g` 安装（Node ≥ 18，推荐 22）。
- FR-14.2 Bun 编译单二进制（`dscode`）跨平台分发。
- FR-14.3 curl 安装脚本。

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 冷启动 | interactive 模式首屏 < 500ms（Node），单二进制 < 100ms |
| 流式延迟 | 首 token < DeepSeek API 延迟 + 200ms（本地处理） |
| 内存 | 闲置 < 80MB；长会话（千条消息）< 200MB |
| 兼容 | Windows / macOS / Linux 三平台；Windows 终端 utf-8 |
| 安全 | key 0600；项目信任机制；危险操作 gate |
| 可观测 | `DSCODE_DEBUG=1` 日志；`--mode json` 结构化事件 |
| 可扩展 | 扩展不超过 200 行实现一个工具 |
| 国际化 | 中英双语，默认中文 |

## 5. 约束与假设

- 假设：用户已具备 Node 18+ 或安装单二进制。
- 约束：不内置任何 LLM，全部走 provider API。
- 约束：闭源 provider SDK 优先用官方（OpenAI/Anthropic），自研 DeepSeek client 走 OpenAI 兼容。
- 约束：v1 不做系统级沙箱（landlock/seatbelt），靠权限规则 + 子进程 + 路径白名单。
- 约束：TUI 自研，不依赖 React/ink 运行时。
