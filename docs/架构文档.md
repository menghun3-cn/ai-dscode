# DSCODE 架构文档

> 版本：v0.1（架构蓝图） · 维护：dscode 团队
> 状态：设计阶段，落地前以本文为准绳

---

## 1. 使命与定位

**DSCODE 是一个对接 DeepSeek 优先、兼容多模型的命令行 AI 编码助手（AI IDE CLI）。**

| 维度 | 取舍 |
|------|------|
| 形态 | 终端 CLI（非 GUI IDE），对标 Claude Code / Codex CLI / pi |
| 首要模型 | DeepSeek（V3.x / R1，含 reasoning 模型） |
| 兼容模型 | OpenAI、Anthropic、本地推理（OpenAI 兼容协议）、其他 OpenRouter 类 |
| 目标用户 | 国内在用 DeepSeek 的开发者、追求私有化/可控成本的团队、需要 headless/CI 集成的人 |
| 差异化 | DeepSeek 一等公民体验 + 中文场景打磨 + 开源 + 可扩展 |

**不做**：GUI IDE 插件、Tab 补全专用模型、远程托管的 SaaS 后端（本地运行，自主可控）。

## 2. 竞品架构调研结论

在选型前，穷尽分析了七款主流产品，提炼共性能力与可借鉴设计：

### 2.1 Claude Code（Anthropic，TS/Node）

- **Agent Loop**：`prompt → LLM → tool_calls → 执行 → 反馈 → 再 LLM`，循环直到无 tool_call。
- **工具集**：Read / Write / Edit / Bash / Glob / Grep / Task（subagent）/ WebFetch / WebSearch。
- **Session**：JSONL，支持 resume / fork / branch。
- **上下文**：`CLAUDE.md`（项目）+ `~/.claude/CLAUDE.md`（全局）+ `.claude/`。
- **MCP**：Model Context Protocol，标准化外部工具/资源接入。
- **Hooks**：`PreToolUse` / `PostToolUse` / `UserPromptSubmit` / `SessionStart` / `Stop`。
- **权限**：allow/deny/ask 规则 + 命令模式匹配 + 白名单。
- **Plan mode**：只读规划不执行，确认后再落地。
- **Sub-agents**：隔离上下文执行子任务，主-agent 不被污染。
- **渲染**：ink（React for CLI）。

**借鉴点**：JSONL session、Agent Loop、MCP、Hooks、Permission、Plan mode、Sub-agent、`AGENT.md` 上下文约定。

### 2.2 Cursor / Cursor CLI（Anysphere）

- **IDE**：VSCode fork，Electron + C++ native(GPU)，TS extension host，远程 `.sh` 后端。
- **Tab 补全**：本地轻量 + 云端大模型混合，延迟优先。
- **Composer**：多文件 agent，远程编排。
- **Cursor CLI**：较新，Codex-compatible 协议，Rust 单二进制，主打 headless / CI。

**借鉴点**：Cursor CLI 的 headless 优先理念（CI 友好、非交互模式同等公民）。

### 2.3 Codex CLI（OpenAI，Rust）

- **实现**：Rust 单二进制，零 Node 依赖，启动快。
- **协议**：OpenAI Responses API，支持 GPT-5-codex 等。
- **工具**：shell / apply_patch / file 编辑。
- **沙箱**：`seatbelt`(macOS) / `landlock`(Linux) 进程级隔离。
- **TUI**：ratatui。
- **审批模式**：`read-only` / `auto-edit` / `full-auto`。

**借鉴点**：审批分级（read-only / auto-edit / full-auto）、沙箱意识（我们落地在子进程 + 路径白名单层面，沙箱系统级留作后续）、OpenAI Responses 协议兼容（DeepSeek 新版已兼容）。

### 2.4 Grok Code（xAI）

- **模型**：Grok 系列，Codex 协议兼容。
- **风格**：快、敢执行，full-auto 激进。
- **形态**：CLI 较轻。

**借鉴点**：协议兼容让多模型快速接入成为可能——这正是 dscode 多 provider 的基础。

### 2.5 OpenCode（SST，TS + Bun）

- **实现**：TypeScript + Bun，开源 MIT，社区驱动。
- **Provider 抽象**：自有 OpenCode Zen 协议 + OpenAI/Anthropic 通用。
- **TUI**：TS TUI 库。
- **LSP 集成**：拿 diagnostics 喂给模型。

**借鉴点**：Bun 运行时（冷启动快、TS 原生、单二进制可编译）、LSP diagnostics 注入上下文、开源社区模式。

### 2.6 pi（earendil-works，TS）—— 本地源码级参考

- **monorepo**：`pi-agent-core`（agent + session runtime）+ `pi-ai`（provider/model 抽象）+ `pi-tui`（组件化终端 UI）。
- **三种运行模式**：interactive TUI / print（`-p`）/ rpc（进程集成）。
- **Session**：JSONL 树状结构，`/tree` 在树节点间跳转、`/fork`、`/clone`。
- **Provider**：40+，含 **DeepSeek 原生支持**（`DEEPSEEK_API_KEY`），OAuth 订阅 + API key + 云厂商（Bedrock/Vertex/Azure）。
- **Extension 系统**：事件 hook（`before_agent_start`/`tool_call`/`tool_result`/`context`/`before_provider_request` 等）+ 自定义工具 + 命令 + TUI 组件 + session 持久化。
- **上下文**：`AGENTS.md`、Skill 系统、prompt 模板。
- **compaction**：上下文压缩，分支摘要。
- **thinking level**：可控推理深度。

**借鉴点**：这是 dscode 最直接、可读源码的参考。借鉴其 monorepo 三包切分、三种运行模式、树状 session、事件驱动 extension、`AGENTS.md` 约定、compaction、provider 抽象。

### 2.7 Kiro（AWS，TS/Node）

- **IDE**：VSCode fork。
- **specs（规格驱动）**：需求 → 设计 → 任务 → 代码的 spec 流程。
- **steering files**：`.kiro/steering/*.md` 影响模型行为。
- **Agent**：spec-kernel，按规格执行，强约束而非自由发挥。

**借鉴点**：spec-first 理念——在 free-form agent 之上提供"规格约束层"，减少失控。dscode 将以"Plan mode + 全局/项目 steering 文件"承载这一理念。

### 2.8 共性能力矩阵

| 能力 | Claude Code | Codex | Cursor CLI | OpenCode | pi | Grok | Kiro |
|------|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| Agent Loop | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 工具（read/write/edit/bash） | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| JSONL Session | ✅ | ✅ | ◐ | ✅ | ✅(树状) | ◐ | ✅ |
| 多 provider | ✅ | ◐ | ◐ | ✅ | ✅(40+) | ✅ | ◐ |
| Hooks/Ext | ✅ | ◐ | ✅ | ✅ | ✅(最全) | ◐ | ✅(steering) |
| MCP | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Plan/Spec 模式 | ✅ | ◐ | ✅ | ◐ | ✅(plan-mode ext) | ◐ | ✅(spec) |
| Sub-agent | ✅ | ◐ | ✅ | ✅ | ✅ | ◐ | ✅ |
| Headless/CI | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ◐ |
| Sandbox 隔离 | ◐ | ✅ | ✅ | ◐ | ◐ | ◐ | ✅ |
| 中文/DeepSeek 一等公民 | ❌ | ❌ | ❌ | ❌ | ◐(原生) | ❌ | ❌ |

**dscode 要做的**：左列能力全打钩，并在最后一行（DeepSeek / 中文）做出差异化。

## 3. 技术路线选型

### 3.1 决策表

| 决策项 | 选型 | 理由 |
|--------|------|------|
| 语言 | **TypeScript** | DeepSeek/OpenAI/Anthropic SDK 生态最稳；TUI/agent 库成熟；pi/opencode 可参照源码 |
| 运行时 | **Node.js ≥ 22**（主）+ **Bun 可选编译**（单二进制分发） | Node 生态稳，Bun 编译出单二进制便于分发与冷启动 |
| 包管理/构建 | **pnpm workspace** monorepo | pi 同款，依赖共享、增量构建 |
| TUI 渲染 | **自研轻量 TUI**（ANSI + Ink 风格的组件树） | ink（React for CLI）成熟但偏重；自研可控、可裁剪到最小；海外抖动小 |
| LLM 协议 | **OpenAI Compatible**（Chat Completions + Responses）为主，**Anthropic Messages** 为辅 | DeepSeek 走 OpenAI 兼容；多 provider 用统一抽象 |
| Session 存储 | **JSONL 树状** | 可 resume/fork/branch，git-friendly，pi 同款 |
| 扩展机制 | **事件驱动 Hooks + 工具/命令注册 + 配置文件（dscode.json）** | pi 已验证此模式最灵活；MCP 作为外部工具标准入 |
| 外部能力 | **MCP client** | 接入第三方工具/资源的开放标准 |
| 配置约定 | **`DSCODE.md`** + **`.dscode/`** | 与 `CLAUDE.md`/`AGENTS.md` 同构，降低迁移成本 |
| 鉴权 | **环境变量 + auth 文件（`~/.dscode/auth.json`）** | DeepSeek/OpenAI key 同套路 |

### 3.2 为什么不用 Rust / Go

- **Rust（Codex 路线）**：单二进制、零依赖、沙箱强，但 TS 生态里的 LLM SDK、TUI、agent 编排更成熟，开发迭代速度对早期项目更重要。沙箱（seatbelt/landlock）列为后续可选增强。
- **Go（bubbletea 路线）**：TUI 生态优秀，但 LLM 生态不如 TS，且团队若 TS 居多则更顺。

选定 **TS + Node + 可选 Bun 编译** 是"开发速度、生态、分发、DeepSeek 兼容"四者的最优平衡。

### 3.3 为什么自研 TUI 而不直接用 ink

- ink（React for CLI）功能强但依赖 React 运行时，体积与启动开销对 CLI 不友好。
- 自研一套"组件树 + ANSI 渲染 + 键盘事件"的极简 TUI（约 800-1500 行），可完全掌控 IME、主题、增量渲染。
- 长期看自研 TUI 是差异化护城河（pi 也是自研 pi-tui）。

## 4. 顶层架构

```
┌─────────────────────────────────────────────────────────────┐
│                         CLI 入口                              │
│  dscode (bin) → args 解析 → 模式分发 (interactive/print/rpc)  │
└──────────────────────┬──────────────────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   ┌─────────┐   ┌──────────┐   ┌─────────┐
   │ TUI 模式 │   │ Print 模式│   │ RPC 模式 │   ← @dscode/modes
   │(交互)    │   │(headless) │   │(集成)    │
   └────┬────┘   └─────┬────┘   └────┬────┘
        │              │              │
        └──────────────┼──────────────┘
                       ▼
        ┌──────────────────────────────┐
        │      AgentSession Runtime       │  ← @dscode/core
        │  (session + agent loop + 工具)  │
        └──────┬───────────────┬─────────┘
               │               │
               ▼               ▼
      ┌──────────────┐  ┌──────────────┐
      │ Provider 抽象 │  │  工具层       │  ← @dscode/ai
      │(DeepSeek 优先)│  │ (read/write/ │
      │ + OpenAI/Anth │  │  edit/bash..)│
      └──────┬───────┘  └──────┬───────┘
             │                 │
             ▼                 ▼
      ┌──────────────┐  ┌──────────────┐
      │ HTTP Client    │  │ 子进程执行    │
      │(流式 SSE)      │  │ (sandbox 可选)│
      └──────────────┘  └──────────────┘
```

### 4.1 三个核心包

| 包 | 职责 | 对标 pi |
|----|------|---------|
| `@dscode/core` | AgentSession Runtime、Session Manager、工具注册与执行、事件总线、compaction、权限、计划模式 | `pi-agent-core` |
| `@dscode/ai` | Provider 抽象、Model 注册、流式响应解析、协议适配（OpenAI/Anthropic/DeepSeek）、鉴权、token 计费统计 | `pi-ai` |
| `@dscode/cli` | CLI 入口、三种模式（TUI/print/rpc）、TUI 组件库、主题、键位、命令路由 | `pi-coding-agent` + `pi-tui` |

> 注：pi 是四包（agent-core/ai/tui/coding-agent）。dscode 把 TUI 并入 CLI 包以降低早期复杂度，等 TUI 成熟再拆 `@dscode/tui`。

### 4.2 关键子系统

#### 4.2.1 AgentSession Runtime（`@dscode/core`）

- 拥有当前 session + 其 cwd 绑定的 services。
- 负责 session 切换/新建/fork 的 teardown + rebuild。
- 事件总线驱动所有 hooks。
- 核心 API（对标 pi `AgentSessionRuntime`）：

```ts
class AgentSessionRuntime {
  get session(): AgentSession;
  get services(): AgentSessionServices;
  get cwd(): string;
  switchSession(path): Promise<{cancelled: boolean}>;
  newSession(opts?): Promise<{cancelled: boolean}>;
  fork(entryId, opts?): Promise<{cancelled: boolean}>;
  dispose(): Promise<void>;
}
```

#### 4.2.2 Agent Loop（核心算法）

```
userPrompt
  ↓
[before_agent_start]  ← hook 可注入消息/改 system prompt
  ↓
[context]            ← hook 可改消息列表
  ↓
┌─► 调用 LLM（流式）
│     ├─► before_provider_headers / before_provider_request
│     ├─► message_start / message_update(逐 token) / message_end
│     └─► after_provider_response
│   ↓
│   LLM 返回 tool_calls?
│   ├─ 是 → [tool_call]（可 block/改入参）
│   │       → 执行工具（并行/串行可选）
│   │       → [tool_result]（可改结果）
│   │       → toolResult 写回 session
│   │       → 回到 ┌─►
│   └─ 否 → agent_end / agent_settled
│
└─► done
```

这是所有竞品的共同内核。dscode 严格按此实现，并支持最多 N 轮 tool call（可配，默认 50，防失控）。

#### 4.2.3 Session Manager（JSONL 树状）

- 存储路径：`~/.dscode/sessions/<cwd-hash>/<session-id>.jsonl`
- 每条 entry：`{id, parentId, type, role, content, timestamp, ...}`
- entry 类型：`user` / `assistant` / `toolResult` / `compaction` / `branchSummary` / `modelChange` / `label` / `extension`
- 树状结构支持：`/tree` 跳转、`/fork`、`/clone`、分支摘要
- `buildContextEntries()`：当前激活分支 + compaction 应用的消息

> 完全对标 pi 的 session 格式，这是经过验证的最优设计。

#### 4.2.4 Provider 抽象（`@dscode/ai`）

```ts
interface Provider {
  id: string;
  api: "openai-chat" | "openai-responses" | "anthropic-messages";
  baseUrl: string;
  apiKey: string | (() => Promise<string>);
  models: ModelDef[];
}

interface ModelDef {
  id: string;
  name: string;
  reasoning: boolean;      // 是否 reasoning 模型（R1）
  contextWindow: number;
  maxTokens: number;
  cost: { input: number; output: number; cacheRead: number; cacheWrite: number };
  input: ("text" | "image" | "audio")[];
}
```

**DeepSeek 一等公民**：
- 内置 DeepSeek 模型目录（`deepseek-chat` / `deepseek-reasoner`），随版本更新。
- 鉴权优先级：CLI `--api-key` → `auth.json` → `DSCODE_API_KEY` 环境变量 → `models.json` 自定义。
- 主变量 `DSCODE_BASE_URL`（默认官方网关）/ `DSCODE_API_KEY`；兼容 `DSAPI_BASE_URL` / `DSAPI_API_KEY`（用户环境已有），支持自定义网关/代理。
- reasoning 模型自动走 `reasoning_content` 字段解析。

**多 provider**：OpenAI、Anthropic、OpenRouter、本地（vLLM/Ollama/LM Studio，走 OpenAI 兼容）。统一抽象，用户可 `--provider` / `/model` 切换。

#### 4.2.5 工具系统

内置工具（对标 Claude Code / pi）：

| 工具 | 说明 |
|------|------|
| `read` | 读文件（支持 offset/limit，图片作为附件） |
| `write` | 创建/覆盖文件 |
| `edit` | 精确文本替换（多 disjoint edit 一次调用，oldText 唯一匹配） |
| `bash` | 执行 shell（超时、信号、cwd、truncation） |
| `glob` | 文件 glob 匹配 |
| `grep` | 内容正则/ripgrep 搜索 |
| `ls` | 列目录 |
| `webfetch` | 抓 URL（headless 模式必备） |
| `task` | sub-agent 隔离上下文执行子任务 |

工具接口：

```ts
interface Tool {
  name: string;
  label?: string;
  description: string;
  parameters: TSchema;       // typebox schema
  execute(toolCallId, params, signal, onUpdate, ctx): Promise<ToolResult>;
  renderCall?(args, theme): string[];   // TUI 渲染
  renderResult?(result, opts, theme): string[];
}
```

#### 4.2.6 权限与审批

借鉴 Codex 的三级模式 + pi 的 hook 拦截：

| 模式 | 行为 |
|------|------|
| `read-only` | 只允许 read/glob/grep/ls，write/edit/bash 全 block |
| `ask`（默认） | 危险操作（write/edit/bash 首次、删除、rm -rf 等）弹确认 |
| `auto-edit` | 文件编辑自动执行，bash 仍需确认 |
| `full-auto` | 全自动（受 allow/deny 规则约束） |

规则配置（`.dscode/permissions.json` + 全局）：

```json
{
  "allow": ["bash:git status", "bash:npm test", "read:**"],
  "deny":  ["bash:rm -rf *", "write:.env", "write:**/secrets/**"],
  "ask":   ["bash:git push *"]
}
```

模式通过模式匹配（minimatch）+ 命令前缀匹配。

#### 4.2.7 上下文与配置

| 文件 | 作用 |
|------|------|
| `DSCODE.md`（项目根） | 项目指令（对标 CLAUDE.md/AGENTS.md） |
| `~/.dscode/DSCODE.md` | 全局指令 |
| `.dscode/settings.json` | 项目设置 |
| `~/.dscode/settings.json` | 全局设置 |
| `.dscode/steering/*.md` | steering 文件（借鉴 Kiro），注入 system prompt |
| `.dscode/permissions.json` | 权限规则 |
| `~/.dscode/auth.json` | 鉴权凭据 |
| `~/.dscode/models.json` | 自定义 provider/model 目录 |
| `~/.dscode/sessions/` | session 存储 |
| `~/.dscode/extensions/` | 全局扩展 |
| `.dscode/extensions/` | 项目扩展 |

system prompt 组装顺序：

```
默认系统提示（角色/工具说明/安全）
+ steering 文件内容
+ DSCODE.md 内容
+ 活动工具 snippets
+ 当前 cwd / skills
+ 用户/flag 追加内容
→ before_agent_start hook 可改
→ context hook 可改 messages
→ before_provider_request 可改 payload
```

#### 4.2.8 Extension/Hook 系统

事件清单（对标 pi，按需裁剪）：

```
session_start / session_shutdown / session_before_switch / session_before_compact
project_trust
resources_discover
before_agent_start / agent_start / agent_end / agent_settled
turn_start / turn_end
message_start / message_update / message_end
tool_call / tool_result / tool_execution_start/update/end
context / before_provider_headers / before_provider_request / after_provider_response
input / user_bash
model_select / thinking_level_select
before_export / before_share
```

扩展导出：

```ts
export default function (dscode: ExtensionAPI) {
  dscode.on("tool_call", async (e, ctx) => {
    if (e.toolName === "bash" && e.input.command.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("危险", "允许 rm -rf?");
      if (!ok) return { block: true, reason: "用户拒绝" };
    }
  });
  dscode.registerTool({ name: "greet", /* ... */ });
  dscode.registerCommand("hello", { handler: async (a, ctx) => { /* ... */ } });
}
```

扩展位置：`~/.dscode/extensions/*.ts`（全局）、`.dscode/extensions/*.ts`（项目，需 project_trust）。
加载：jiti（TS 原生，免编译）。

#### 4.2.9 三种运行模式

| 模式 | 触发 | 用途 | UI |
|------|------|------|----|
| interactive | `dscode`（默认） | 日常交互 | TUI |
| print | `dscode -p "..."` | 一次性首尾 / 管道 / CI | 纯文本输出 |
| rpc | `dscode --mode rpc` | 进程集成（IDE 扩展宿主） | JSON-RPC over stdio |

print 模式同等公民，确保 CI/headless 友好（借鉴 Cursor CLI）。rpc 模式让未来写"dscode 的 VSCode 扩展"成为可能。

#### 4.2.10 Compaction（上下文压缩）

借鉴 pi：
- 阈值触发（token 达 contextWindow 80%）或 `/compact` 手动或 overflow 恢复。
- 用一次 LLM 调用对"将被丢弃的旧消息"生成摘要，写入 `compaction` entry。
- 后续 `buildContextEntries()` 用摘要替代旧消息。
- 扩展可自定义摘要逻辑（`session_before_compact` 返回 `{compaction:{summary}}`）。
- 分支切换（`/tree`）时对"被放弃的分支"做 branch summary。

---

## 5. 数据流：一次完整请求

以 `dscode "重构 auth 模块"` 为例：

1. CLI 解析 args，分发到 interactive 模式。
2. `createAgentSessionRuntime`：加载 services（provider registry、session manager、tool registry、event bus）。
3. `session_start` 事件 → 扩展初始化。
4. `resources_discover` → 注入额外 skill/prompt 路径。
5. 用户输入 → `input` 事件（可 transform/handle）。
6. `before_agent_start` → 注入 steering / DSCODE.md / 改 system prompt。
7. Agent Loop 第 1 轮：
   - `context` → 消息整理 → `before_provider_request` → 调 DeepSeek（流式）。
   - `message_update` 逐 token 流式渲染到 TUI。
   - LLM 返回 tool_calls（如 `read src/auth.ts` + `bash git log`）。
   - `tool_call` → 权限检查 → `bash` 在 ask 模式需确认 → 执行 → `tool_result`。
   - toolResult 写回 session。
8. Agent Loop 第 2..N 轮：LLM 看到 tool results，决定继续 `edit` 或结束。
9. 无 tool_call → `agent_end` / `agent_settled`。
10. TUI 渲染最终 markdown。

## 6. 安全模型

| 层 | 措施 |
|----|------|
| 鉴权 | key 仅存 `~/.dscode/auth.json`（0600），支持 keychain 命令 (`!security ...`)、env 插值 |
| 项目信任 | `project_trust` hook + `trust.json`，项目扩展需显式信任 |
| 权限 | allow/deny/ask 规则 + 审批模式分级 |
| 子进程 | bash 工具在 cwd 子进程执行，超时 + 信号可控；后续可加 landlock/seatbelt |
| 路径保护 | deny 规则覆盖 `.env`、`secrets/` 等 |
| 上下文 | DSCODE.md 与 steering 文件经信任才加载 |
| 输出 | 不把敏感凭据写入 session 文件（扩展负责脱敏） |

## 7. 性能与成本

- **流式优先**：所有 LLM 调用流式，TUI 边收边渲。
- **token 缓存**：provider 层支持 prompt cache（DeepSeek 的 context caching）。
- **compaction**：避免长对话爆 context。
- **并发工具**：同一 assistant message 的多个 tool_call 并行执行（默认）。
- **TUI 增量渲染**：组件缓存 + `invalidate()`，仅状态变化时重渲染。
- **计费统计**：每 turn 记录 input/output/cache token 与成本，session 累计。
- **冷启动**：Node 22 + 极简依赖，目标 < 200ms。Bun 编译单二进制 < 50ms。

## 9. 与 pi 的关系（坦诚说明）

dscode 深度参考 pi 的 monorepo 切分、session 格式、extension 事件模型——这些是经 pi 验证的最优设计。差异：

- dscode **DeepSeek 优先**，pi 是 provider 平权。
- dscode **中文场景打磨**（默认中文提示、中文错误、中文文档）。
- dscode **TUI 并入 CLI 包**（早期精简），pi 独立 pi-tui。
- dscode **DSCODE.md** 约定（自有命名），pi 用 AGENTS.md。
- dscode **沿用 OpenAI 兼容**为主协议，pi 自有 router 层。
- dscode 开源协议待定（倾向 Apache-2.0），pi 闭源。

尊重 pi 的工作：凡是借鉴的设计，在代码注释与文档中注明出处。
