# DSCODE 成功标准

> 版本：v0.1 · 原则：可验证、有证据、能闭环
> 配套：架构文档.md / 需求文档.md / todos-list.md

---

## 0. 评判总则

本文件每一条**必须是可执行的验证**，不是愿望。
- ✅ "在空仓库跑 `dscode -p '初始化一个 node 项目'`，生成的 `package.json` 存在且 `npm i` 成功" —— 可验证
- ❌ "体验流畅" —— 不可验证（禁止出现在本文件）

每条带 ID、验证手段、通过判据。里程碑结束时逐条打勾并贴证据。

## Milestone 1：MVP 闭环（v0.1）

> 目标：DeepSeek 单 provider + 四工具 + interactive/print，能在一仓库里完成"读→改→测"闭环。

### SC-1.1 启动与鉴权
- **ID** SC-1.1
- **验证**：无任何配置时运行 `dscode`，提示输入 DeepSeek key；输入后 `~/.dscode/auth.json` 存在且权限为 0600（Windows 检查 ACL/user-only）。
- **通过**：文件存在、内容含 `{"deepseek":{"type":"api_key","key":"sk-..."}}`、权限合规。
- **证据**：`cat ~/.dscode/auth.json`（脱敏）+ `ls -l`。

### SC-1.2 环境变量鉴权
- **ID** SC-1.2
- **验证**：`DEEPSEEK_API_KEY=sk-... dscode -p "echo hello"` 不读 auth 文件直接成功。
- **通过**：模型回复非空、无鉴权错误。

### SC-1.3 read 工具
- **ID** SC-1.3
- **验证**：准备 `a.txt` 内容 `hello`；`dscode -p "读取 a.txt 并复述内容"`。
- **通过**：回复包含 `hello`，session JSONL 含 read tool 调用记录。

### SC-1.4 write 工具
- **ID** SC-1.4
- **验证**：`dscode -p "创建文件 b.txt 内容为 world"`。
- **通过**：`b.txt` 存在且内容 `world`。

### SC-1.5 edit 工具
- **ID** SC-1.5
- **验证**：`c.txt` 内容 `foo bar`；`dscode -p "把 c.txt 里的 foo 改成 baz"`。
- **通过**：`c.txt` 内容变为 `baz bar`。

### SC-1.6 bash 工具
- **ID** SC-1.6
- **验证**：`dscode -p "运行 node -e 'console.log(1+1)' 并告诉我结果"`。
- **通过**：回复含 `2`，session 含 bash 调用与退出码 0。

### SC-1.7 Agent Loop 多轮
- **ID** SC-1.7
- **验证**：在一个有 `package.json` 的 node 项目里 `dscode -p "跑 npm test，如果失败就修复直到通过"`（准备一个会失败再可修的测试）。
- **通过**：最终 `npm test` 退出码 0，session 含 ≥2 轮 tool 调用。

### SC-1.8 print 模式管道
- **ID** SC-1.8
- **验证**：`echo "总结这句话" | dscode -p -` 收 stdin 作为 prompt。
- **通过**：输出非空摘要。

### SC-1.9 interactive 基本可用
- **ID** SC-1.9
- **验证**：`dscode` 启动 TUI，输入"列出当前目录文件"，能看到流式输出与 `ls` 工具调用渲染。
- **通过**：TUI 不崩、输出可见、`Ctrl+C` 可中断、`/exit` 退出。
- **MVP 最小边界**：单行输入 + 滚动输出即可；组件树 / `@` 文件引用 / `!` 命令 / IME 候选框定位**不属本里程碑**（P1 打磨项）。多行输入、`@`、`!`、IME 的验收后置，不阻塞 M1 关闭。

### SC-1.10 中文回退
- **ID** SC-1.10
- **验证**：用中文提问"用中文回答：什么是闭包"。
- **通过**：模型输出中文、TUI 中文不截断/错位。

## 非功能验证

### NFR-1 冷启动
- **验证**：`time dscode --version` ≤ 200ms（单二进制）/ 500ms（Node）。
- **证据**：`time` 输出。

### NFR-2 内存
- **验证**：跑 500 条消息长会话，`ps` RSS ≤ 200MB。

### NFR-3 流式延迟
- **验证**：`dscode -p "写一首关于秋天的诗" --mode json`，记录首个 message_update event 的时间戳 vs 请求发出时间。
- **通过**：差值 ≤ DeepSeek 首 token 延迟 + 200ms。

### NFR-4 可观测
- **验证**：`DSCODE_DEBUG=1 dscode -p hi` 产生 `~/.dscode/logs/` 日志。
- **通过**：日志含请求/响应/工具调用。
- **附加判据（M1 起）**：日志含**每轮收敛原因**（settled / max-turns / error）与**每 turn usage**（input/output/cache token，可换算成本）——SC-1.7 长 loop 失败时可定位"哪一轮、哪个工具、为什么停"。

## 失败定义（什么不算成功）

- ❌ 任何 SC 条目在里程碑结束时未通过且无证据。
- ❌ "差不多能跑"——必须贴 `cat`/`test`/`time` 实测输出。
- ❌ 只在开发者机器跑通——跨平台至少 Windows+Linux 验证。
- ❌ 中文在 TUI 错位/截断。
